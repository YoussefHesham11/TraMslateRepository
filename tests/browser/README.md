# Browser checks

These drive real headless Chrome over the DevTools protocol (`cdp.cjs` — a small
hand-rolled client, no Playwright or Puppeteer dependency). They exist because
the editor's layout defects live in CSS and in measured scrolling: the Node DOM
stub in `../editor-state.test.cjs` cannot observe them.

## Running

```text
node tests/browser/check-all.cjs          # layout, workflow, performance
node tests/browser/check-all.cjs --app    # …plus a tour of the running app
```

The `--app` tour needs the application listening on <http://127.0.0.1:5199> and a
reachable database:

```text
dotnet run --no-launch-profile
```

(with `ASPNETCORE_URLS=http://127.0.0.1:5199`).

## What each one does

| File | Purpose |
|---|---|
| `build-harness.cjs` | Builds `editor-harness.html` from the real Razor view, stylesheets and editor scripts. Regenerated by every run, so it never drifts from the app. |
| `harness-boot.js` | Answers the studio API with synthetic cues. Everything else, including the video, goes to the real network layer. |
| `harness-measure.js` | Measures the layout once the real renderer has drawn, and publishes a report the runner reads. |
| `layout-check.cjs` | Asserts at six window sizes that the timeline never covers the cue list and the open card always fits. |
| `workflow-check.cjs` | Steps through cues as a translator does; checks visibility, focus, typing, timeline clicks and profile switching. |
| `perf.cjs` | Render, selection, keystroke and quality-sweep timings at 1500 cues, with a budget that fails. |
| `app-tour.cjs` | Signs in, creates a project, saves to SQL Server, reloads, and proves a stale save is refused without data loss. Screenshots to `shots/`. |
| `clean-tour-data.cjs` | Removes projects a failed tour run stranded. |
| `probe.cjs`, `probe-live.cjs` | Ad-hoc diagnostics: print element heights, or evaluate an arbitrary expression in the harness or the live editor. |
| `shot.cjs` | Screenshot the harness at a given content size. |

## A note on window sizes

Chrome counts browser furniture in `--window-size`, roughly 152px of it. The
scripts pad for that, so the sizes named in the checks are *content* heights —
what the page actually gets.

## Generated files

`editor-harness.html`, `shots/` and any `*.png` are build output and can be
deleted at any time.
